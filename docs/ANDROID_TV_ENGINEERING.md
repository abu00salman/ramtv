# RaM TV engineering report — 2026-10-12

This change is an independently implemented stability and Android TV iteration,
not a claim that all requested work or device qualification is complete.
The original name, assets, package ID, signing script, native iPhone source and
existing playback features are retained. Changes target only abu00salman/ramtv.

## Repository audit and priorities

The repository has a native Swift iPhone application and a separate Flutter
application in app/ for Android, Android TV, Windows and macOS. Native platform
scaffolds for Flutter are generated by ci/prepare.sh; Android TV configuration
therefore belongs in ci/patch.py, not an untracked generated manifest.

| Priority | Finding | Result |
| --- | --- | --- |
| P0 | Reconnect timer survives a channel switch; concurrent native opens race | Cancel timer, invalidate older queued work, serialize stop/open/dispose, catch failed opens |
| P0 | Fixed retry delays and early budget resets can repeatedly reopen unstable streams | Bounded exponential delays of 1/2/4/8/16/32 seconds; reset after 30 seconds of continuous playing without buffering |
| P0 | Concurrent source refreshes can overwrite newer data | Close superseded HTTP clients and guard publication with a generation |
| P0 | Errors can display provider URLs and credentials | Replace raw playback/source exceptions with safe messages |
| P1 | Temporary provider failure removes its last usable catalogue | Preserve that provider's previous entries while reporting refresh failure |
| P1 | Corrupt saved entries can prevent startup | Decode valid entries individually and validate saved resume values |
| P1 | Xtream item construction and M3U byte decoding run on the UI isolate | Move both to compute; iterate M3U lines without an intermediate list |
| P1 | EXTINF commas truncate titles; query tokens interfere with container classification | Parse the first unquoted separator and inspect URI paths |
| P1 | Width heuristic misses lower resolution TVs | Android UiModeManager bridge selects TV layout independently of width |
| P1 | Some TV Select buttons do not activate Flutter cards | Explicit Select-to-ActivateIntent mapping; RTL widget coverage |
| P1 | Player Back exits immediately; modal focus can be stolen by control auto-hide | First Back hides controls; suspend auto-hide while channel list/EPG is open |
| P1 | No EPG in Flutter | Optional Xtream short EPG, Arabic/Base64 titles, UTC timestamps, bounded provider-scoped 60-second cache, current programme and guide |
| P1 | LAN portal uses weak short PIN and unbounded uploads | Secure random six-digit PIN, five-failure limit, 16 KiB body limit, timeout, no-store headers, bind/stop lifecycle guard |
| P1 | Manifest patch misses TV declarations if INTERNET is already present | Independent declarations, idempotent attributes and launcher category, real-device bridge test |
| P1 | CI builds without analysis/tests and can release partial failed builds | Quality gate, pinned tested Flutter, dependency lock, release requires successful jobs |
| P0 follow-up | Flutter sources, history and catalogue URLs remain in ordinary app storage | Full credential-vault and cache migration still required; Android cloud backup disabled as mitigation |

## References and licensing

GitHub's topic page could not be fetched through the connector. Repository search
using topic:iptv license:mit identified projects for source study.

* [IPTVnator](https://github.com/4gray/iptvnator), MIT: inspected its EPG
  programme cache and embedded-mpv reconnect coordinator. Useful principles:
  provider-scoped cache keys, bounded expiry, request retirement, stable-playback
  retry reset and teardown cancellation.
* [my-tv-0](https://github.com/lizongying/my-tv-0), MIT: inspected
  PlayerFragment.kt. It uses Media3/ExoPlayer, MediaCodec renderer selection,
  listener-based errors and explicit release of the previous player.
* [AndroidX Media3](https://github.com/androidx/media), Apache-2.0: inspected
  DefaultLoadControl. Native Android load control and hardware integration are
  valuable candidates for a later controlled comparison.
* [media_kit](https://github.com/media-kit/media-kit), MIT wrapper: inspected its
  public API and the resolved native implementation. RaM TV already relies on
  this cross-platform engine. No reference code, branding, assets or channel
  lists were copied into this change.

| Engine | Technical fit | Decision and evidence limit |
| --- | --- | --- |
| media_kit/mpv | Existing Flutter integration, desktop support, audio/subtitle controls, broad demuxing | Retained; analyzed and compiled as part of the existing application |
| Media3/ExoPlayer | Native Android lifecycle, hardware codec integration, explicit load control | No device comparison performed; replacing the current engine is not justified |

No startup-latency, buffering, codec, memory or superiority measurement is claimed.
Automatic adjacent-channel preloading was not introduced: concurrent provider
connections and memory cost need licensed-server/device measurements first.
Existing native buffering defaults were retained for the same reason.

## Validation

Environment: Debian 13, Flutter 3.47.7, Dart 3.13.5; isolated Android SDK and JDK
17 were prepared for the APK build. Initial build attempts exposed missing SDK
components, incomplete system Java and JVM proxy/CA setup; these are environment
issues and are recorded rather than counted as successful builds.

* Flutter analyze: passed with no issues.
* Flutter test: 21 tests passed, including 20,000-channel M3U input,
  Xtream isolate construction, source refresh races, corrupt persisted entries,
  playback queue failure/disposal, EPG boundaries/expiry, RTL Select, text-field
  focus, low-resolution TV detection and a loopback HTTP portal test.
* Python Android patch test: passed; checks idempotence, Leanback, optional
  touchscreen, native detection bridge and preservation of INTERNET.
* bash -n for platform build scripts and git diff --check: passed.
* adb devices: no attached Android device or simulator.
* Android release APK: ARM64, ARM32 and x86_64 builds passed. aapt confirmed
  com.ramzi.ramtv, RaM tv label, Leanback launcher and the original TV banner;
  apksigner verified the APK. Minimum SDK from the current generated scaffold
  is 24; older Android devices were not qualified.
* APKs use a local Android debug certificate in release mode. The existing CI
  signing secret was unavailable locally; these builds are not verified as
  installable updates over an existing signed installation.
* GitHub publication: branch creation through the connector and git push both
  returned 403. CLI authentication succeeds as abu00salman, but the connection
  cannot write this repository. No remote branch, PR or Actions run was created.
  Local branch, commit, patch, bundle and draft PR text are prepared.
* iPhone, Windows and macOS: no local build/runtime validation on this Linux
  host. Existing build jobs remain in GitHub Actions; their results must be
  checked before merging.

## Remaining qualification and work

Keep this PR in draft until physical-device and other-platform review.
Priority follow-ups: encrypted credential/cache migration with recovery tests;
XMLTV/M3U EPG association; provider-scoped identifier migration; complete remote
navigation coverage for all screens; large-list search indexing; real stream
stall/watchdog tests; Media3 comparison; live/VOD buffering and memory profiles;
HLS/TS/MP4/MKV hardware/software codec and subtitle/audio-track matrices.

For device review, use only the owner's licensed provider: rapid channel
switches, network loss/recovery, six failed retries/manual Retry, pause, Back,
channel list/EPG focus, Arabic RTL, VOD/episode resume and sustained playback.
The active native open is allowed to settle before the next serialized stop;
generation cancellation prevents superseded queued opens, not instantaneous
interruption of an already executing native call. Validate this latency on TV.
